# Rover 4.7.2 — два ESC на DisplayPort OSD

СТАТУС: экспериментальный комплект исходных изменений. НЕ готовая прошивка.
Компиляция и испытание на контроллере автором архива не выполнены.

Цель: Pixhawk1-1M-bdshot, Rover-4.7.2, upstream commit fb773567.
Скрипт добавляет независимые ESC2TEMP и ESC2RPM, ESC2_IDX (по умолчанию 10).
Штатные ESCTEMP/ESCRPM остаются без изменений; для них выберите ESC_IDX=9.
Новые функции копируют штатные рендереры с заменой селектора ESC.
Индексы параметров добавляются в var_info2, старые не перенумеровываются.
Скрипт прерывается при несовпадении ожидаемых якорей исходного кода.
Масштаб оборотов, единицы температуры и обработка отсутствующей телеметрии
наследуются от штатных функций: RPM не пересчитывается дополнительно.

## GitHub Actions
1. Создайте пустой GitHub-репозиторий.
2. Распакуйте архив. Поместите его содержимое в корень репозитория,
   обязательно включая скрытую папку .github и папку tools.
   При загрузке через сайт GitHub при необходимости создайте файл
   .github/workflows/build.yml вручную из содержимого архива.
3. Откройте Actions → Rover 4.7.2 dual ESC OSD → Run workflow.
4. Дождитесь зеленого результата. В Artifacts появится архив с .apj,
   .elf, примененным diff, идентификатором исходников и контрольной суммой.
   Если сборка красная, НЕ прошивайте частичные результаты: нужен журнал ошибки.

Сборка требует интернета и ресурсов GitHub Actions. Проверьте доступную квоту
и возможную стоимость в вашем аккаунте перед запуском. Архив ничего сам
не публикует, не прошивает и не запускает автоматически.
Зависимости и actions не закреплены по криптографическим хешам; это не
герметичная воспроизводимая сборка и не гарантия идентичности стоковому образу.

## Настройка после успешной сборки
Сохраните полный .param и исходный .apj до любых изменений.
Загружать следует только ardurover.apj из успешной сборки.
После прошивки и перезагрузки заново загрузите список параметров.
Файл osd-screen1-example.param меняет ТОЛЬКО поля экрана 1 и их координаты.
Не импортируйте его вслепую: сначала проверьте, что не перекрываете другие поля.
SERIAL, протокол DisplayPort, настройки ESC и DShot намеренно не изменяются.
В обычном редакторе OSD нестандартные поля могут не появиться: задавайте их
через полный список параметров. Для другого экрана замените OSD1_ на OSD2_ и т.д.

## Стендовая проверка обязательна
Отключите силовое питание двигателей при первой проверке загрузки.
Затем закрепите аппарат и исключите контакт с вращающимися частями.
Сверьте каждое из четырех показаний с телеметрией ESC9/ESC10 отдельно.
Проверьте исчезновение/старение данных, остановку моторов и смену экранов.
До проверки не используйте сборку в движении. При сбое верните исходный .apj.

## Состав
- tools/patch_dual_esc.py — преобразование чистого исходника;
- tools/check_apj.py — структурная проверка результата (не тест работы OSD);
- .github/workflows/build.yml — загрузка исходников, патч и компиляция;
- osd-screen1-example.param — пример расположения полей;
- stock-metadata.json — метаданные пользовательского стокового образа.
Стоковый .apj и готовый модифицированный бинарник в архив не включены.
